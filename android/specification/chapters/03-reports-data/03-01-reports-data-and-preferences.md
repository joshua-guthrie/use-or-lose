# Chapter 03.01 · Reports, data, and preferences

This inventory extends the app specification to the desktop Calendar menus, Analytics companion, chart tools, and relevant data commands. The [parity matrix](../../verification/feature-parity.md) records the Android disposition and acceptance case for each capability. The screenshots and data contracts are the deliverables of later milestones.

## Reports

From Calendar tap the bottom **Reports** tab, then choose any analytics view in the report list. Reports opens on a useful year and shows that leave year and its actual dates. A year change or **Refresh** reloads a read-only snapshot. Each result keeps its year, filters, and snapshot identity. Show progress, empty results, warnings and retry on failure. Keep a rejected, cancelled, or obsolete result from replacing the current selection. Charts, their exact tables, and contributing entries use the same read-only result and the same presentation for effective past and future entries. Use an explicit **View entries** action and retain the report's scroll position and filters on return. [Exact tap paths for all reports](../01-calendar/01-07-menu-structure.md#reports-and-analytics)

## Data and maintenance

**Data and backups** exposes **Share backup**, **Restore backup**, and the data health check. Read and write the CLI's schema-v1 portable archive and accept the compatible single-year input. The working ledger uses the same canonical desktop JSON. Archive merge keeps an existing transaction when its ID collides within that year and adds incoming IDs that are absent. Existing configuration and holiday-cache files stay authoritative in merge mode. Replace acts on included matching files and preserves unrelated years. Preview before writing, including collision counts and any dependency or validation issues. The storage milestone defines the complete validation, interrupted-restore recovery and Windows and Linux round-trip cases. [Desktop backup/import code](../../../../src/useorlose/commands/data.py#L286) · [Backup tests](../../../../tests/test_export_import.py)

**Reconcile entry** is an advanced manual action on a source transaction or day. The user enters the new hours and reason and reviews the matched row before applying. When multiple rows match, require the user to choose one. [Payroll reconciliation](../../../../src/useorlose/commands/transactions.py#L456)

**Check data** is read-only and reports relevant malformed ledgers, invalid rows, and lineage warnings with the affected year. **Review carryover** includes recovery and opens the relevant generated-record review. For duplicated legacy opening mirrors, offer explicit repair only after identifying an affected ledger and showing old and revised values. Review and separate confirmation are required. [Desktop validation](../../../../src/useorlose/commands/data.py#L562) · [Legacy repair and recovery](../../../../README.md#preview-source-edits-and-reconciliation)

## Calendar settings and help

- A year chooser lists discovered leave years and real dates. It moves Calendar browsing in the chosen year. A year change preserves the current balance cutoff. The user can change the cutoff from **Balances & date**. Reports can independently select an available year. Reopen Calendar on the current date. Use **Refresh** to reread local data when a workflow provides it. [Desktop year chooser](../../../../src/useorlose_gui/main_window.py#L2334) · [Year metadata](../../../../src/useorlose/commands/data.py#L35)
- Give the user Sunday or Monday as the week start, a 0–13 day payday offset for display, and Calendar visibility controls for automatic accruals, holidays, paydays and period ends. Respect Android font scaling. Treat payday and marker controls as presentation choices. They leave accounting cutoffs intact. The balance picker always identifies pay-period ends. Keep reminder thresholds as local choices in pay periods with the desktop's default 1, 3, 6, and 12. [Calendar preferences](../../../../src/useorlose_gui/main_window.py#L564)
- Holiday handling reads compatible cached dates offline, including dates restored from a Use or Lose backup. Provide a way to review dates and regenerate from supported offline rules. Preserve the last valid cache on a failed refresh. [Device storage decision](../04-architecture/04-02-device-storage.md#canonical-private-storage) · [Holiday dates and cache](../../../../src/useorlose/holidays.py)
- Accounting settings show the work tour, increment, accrual defaults, and category policies used for results. Provide a review step for changing the tour or recording the actual date from which FMLA history is complete. Preserve captured tours on past transactions. Keep unsupported editing fields readable and carry them intact through backup. Decide which agency-specific rules need direct editing after comparing existing stores. [Desktop config model](../../../../src/useorlose/config.py#L23) · [FMLA history guide](../../../../docs/PARENTAL_LEAVE.md)
- Expose app help, leave abbreviations, version and project/site information. Help is bundled, searchable or grouped by task, and written in app terms. Give version detail for support and identify the project website as an external navigation action. Use platform font scaling, normal Android Back, and system behavior for app and store updates. [Desktop help and About](../../../../src/useorlose_gui/main_window.py#L2303)

## Desktop-specific and deferred features

- The first release defers What-if Planner. Dated ledger entries and balance projections remain in scope. [Issue #147](https://github.com/joshua-guthrie/fedleave/issues/147)
- Android uses a private built-in data store and calculator. Alternate backend executables, arbitrary working-data directories, desktop installer update prompts, a persistent PDF destination, printing, and forced close are desktop controls. The phone uses private storage, backup restore, platform sharing, Play updates, and normal app navigation. [Desktop settings](../../../../src/useorlose_gui/settings.py) · [Calendar menus](../../../../src/useorlose_gui/main_window.py#L1511)
- CLI aliases, output modes, raw developer snapshots and command help remain developer tooling. The phone exposes the user workflows with app labels. MCP and AI integrations stay on desktop. Reports or charts may be shared as the supported graphics and PDFs. The phone provides an on-screen table for exact chart values. [Console and companion entry points](../../../../pyproject.toml#L54) · [Issue #151](https://github.com/joshua-guthrie/fedleave/issues/151)
