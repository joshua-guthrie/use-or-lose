## Findings

Start with correctness, regressions, data integrity, platform behavior, tests and visual or accessibility differences. Give each actionable finding a stable ID. Identify the affected lines and case, the observed failure or missing evidence, and the expected behavior. A confirmed clean review records the reviewed scope and evidence.

## Coverage of the final candidate

Record which entry points, failure paths, tests, screenshots and neighboring features were inspected. Identify unverified work that prevents an applicable gate from passing. Keep source evidence synthetic and sanitized. Include the final reviewed revision and one of Pass, Fail, or Blocked. Link the QA report so the recorded decision covers the same build and evidence.

For delegated work, record the applicable [candidate verdict](../../specification/chapters/07-organization/07-02-multi-model-development-workflow.md#review-and-approval) and the findings and evidence it cites. Assess test independence, code navigation, and the clarity of changed interfaces and Python explanations where applicable.
