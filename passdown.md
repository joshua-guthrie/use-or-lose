# Use or Lose Android planning passdown

## Product rename, repository migration, and 1.0.0 release (November 26, 2026)

- The application is renamed from FedLeave to **Use or Lose** everywhere user-visible (desktop windows/dialogs, CLI banners, PDF report title, Android label and wordmarks, mockup boards). Internal identifiers stay: the `fedleave` CLI command, the Python package, the `com.westmouthbay.fedleave` app ID, and the app-private data directory.
- The repository moved to **github.com/joshua-guthrie/use-or-lose**. History was migrated complete but with every installer binary and committed `dist/` build stripped (git 865 MB → 17 MB); the old repo was renamed `fedleave-deprecated` and stays until the owner moves the westmouthbay.com links, after which deleting it reclaims the account LFS quota (the installers were LFS objects).
- Desktop distribution is now **on demand**: the Distribution workflow runs only on `workflow_dispatch`; a release publishes desktop installers only (no Android artifacts) and commits just `installers/BUILD.txt`. No rolling beta channel; no binaries in git.
- **Release v1.0.0** ("Use or Lose 1.0.0", desktop only) is published on the new repo. The Android fixture parity source stays pinned to `7041ce9e` until the next parity pass re-verifies against v1.0.0.

## Decisions to carry forward

- The version-controlled project root is `android/`. The specification, implementation briefs, QA reports, AI code reviews, and deliverables have defined locations. [Project organization](android/specification/chapters/07-organization/07-01-project-organization.md)
- The phone spec will account for each desktop capability and link every phone workflow to annotated mockups and acceptance tests. Kotlin, Compose, and Android Studio are the recommended starting point. The existing desktop CLI stays available through its callable core.
- Android Calendar should have one **Balances** panel. It opens at **As of today**. A date picker marks pay-period ends, and selecting a date updates the same panel. Show future dates as projections and include expandable earned and used details at pay-period close.
- Prompt from the task when Today or a deliberate future request needs a missing leave year. Preview before creating, resolve by stored dates, and suggest carryover from an eligible adjacent source. [Draft ledger requirements](android/specification/chapters/02-ledger/02-01-ledger-and-leave-years.md)
- Keep the desktop-compatible JSON store on the phone. **Restore backup** is the sole inbound file workflow. Use the Android Sharesheet for supported reports, images, and existing-format backups.
- Agent model routing (opencode, `.opencode/agents/`): `coder` runs DeepSeek V4 Pro and `image` runs DeepSeek Flash (vision), both at `max` effort. `planner` runs Sol 6.2 (`openai/gpt-6.2-sol`) at `xhigh` for planning, architecture, review and other Sol-led work, but stays on DeepSeek V4 Pro at `max` while the OpenAI Pro usage limit is exhausted (flip both planner lines when usage resets). Vision fallback: if Flash cannot view images, re-run the image agent on `openai/gpt-6.2-sol`. The unspecified-agent default model is DeepSeek V4 Pro at `max` (project `opencode.json`).
- Treat 30% remaining in the five-hour window as the cutoff. Record a passdown and make a local commit at each specification milestone. Split large milestones by screen or behavior, and record a final checkpoint if the window ends mid-milestone.
